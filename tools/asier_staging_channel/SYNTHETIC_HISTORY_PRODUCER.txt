Entry: syntheticPrivateHistoryProducerV1. Only explicit SYNTHETIC_ONLY invokes

Process protocol
- The fixed synthetic IDs alone are sent to stdin, without shell interpolation.
- Binary stdout feeds the previously reviewed bounded Git batch decoder. Receipt
  is accepted only after stdin finish, exit0, stdout end and matching close0.
  exit alone never establishes output completion. stderr is discarded/cleared.
- Output/IO/child errors, overflow and deadline trigger own-child termination.
  SIGTERM, bounded wait, SIGKILL and bounded wait are attempted without retry.
  Missing close means BLOCKED/cleanup UNKNOWN, not process absence. Late bytes
  are cleared and late errors absorbed; returned metadata does not turn green.
- No raw error/command/path/output buffer enters the JSON-safe receipt. Its
  nonenumerable one-shot takeObjects method transfers buffer ownership; dispose
  clears untaken data. Consumer must clear transferred buffers independently.
- Synthetic Node child fixtures test actual process/stdout closure, including a
  bounded writer whose output arrives after its owning child's exit event.
  These Node fixtures do not attest Git provenance or a real Git invocation.

Private storage protocol
- Existing Linux descriptor traversal/0700 effective-uid private parent is reused.
  A nonce directory is created through that retained parent descriptor. Exactly
  three regular0600 files use exclusive/no-follow creation; exact captured IDs,
  Git hash, bytes, same filesystem and file identities are verified. Sync/close
  precede the synthetic consumer. Inputs are captured once before any await.
- Consumer receives a transient private path only as a trusted callback argument;
  it is never a report field. The JSON-safe result contains fixed codes/counts.
- On success or failure, independent cleanup unlinks only original identity-
  matching files. Replaced or additional files survive and force BLOCKED.
  No recursive delete, parent/repository/image deletion or overwrite exists.
  Empty nonce directory removal is checked against its retained original inode;
  already-removed original storage is distinguished from a replacement path.
- All owned buffers and acquired handles are cleaned even when consumer throws.
  Cleanup failure/unknown is reported honestly and cannot produce an accepted
  transfer. This is not secure erasure or protection against hostile same uid,
  root, compromised kernel/storage or indefinitely blocked kernel I/O.
