Structured future command
fixedGitProducerCommandV1 validates a canonical absolute Linux repository path
and returns only private argv/environment accessors. Nothing is executed and no
path/command is enumerable in JSON. Arguments are fixed, without a shell:
--no-lazy-fetch --no-replace-objects --no-optional-locks --no-pager
-c safe.directory=<path> -c core.hooksPath=/dev/null -c core.fsmonitor=false
-c credential.helper= -c protocol.allow=never -C <path> cat-file --batch
Repository path remains one argument even with spaces; control, relative, URL,
traversal or noncanonical paths are rejected. Repository identity, trust, object
availability and authorization are NOT established by this lexical constructor.

Environment is newly constructed, not inherited: LC_ALL=C, disabled global/system
Git config, prompt, lazy fetch, replacement objects and optional locks. No HOME,
PATH, credential, SSH, tracing, LD_* or GIT_CONFIG_COUNT variables are copied.
These flags are Git controls, not an OS network sandbox or proof of provenance.

Metadata-only entry
gitExecutableMetadataPreflightV1 needs explicit EXECUTABLE_METADATA_ONLY mode,
independently reviewed expected SHA256 and exact version, and a trusted Linux
executable. Tests use controlled private Node script fixtures, never actual Git.
No actual executable/preflight invocation is authorized merely by this source.

The named candidate must be canonical/nonsymlink, regular/single-link, root or
effective-uid owned, not group/world writable and executable, 1byte..64MiB.
It is opened O_NOFOLLOW, its named and descriptor identities matched, and SHA256
computed from bounded reads. BigInt identity/mode/ownership/size/nanosecond times
are checked before and after each probe and against the named file at completion.
Children execute via /proc/<parentpid>/fd/<retainedfd>, preserving the opened file
identity. Trusted procfs/runtime/filesystem and stable root/euid remain premises.

Only these fixed probes can execute, with cwd=/, stdin ignored, shell false,
fresh environment, SIGKILL timeout<=5s and bounded stdout/stderr:
1. --version (exit0)
2. --no-lazy-fetch --no-replace-objects --no-optional-locks --no-pager --version

No repository, remote, object lookup, Git help pager, filters or stdin values.
Flag acceptance/help advertisement is recorded as such, not semantic validation
of actual object transport. Pure capture parser has no execution authority.

All raw captured bytes remain private and are cleared; raw errors/help/path/env
never enter the safe result. Only fixed codes, version, SHA256, counts and closed
capability booleans are returned. JS strings/engine copies are not secure erasure.
spawnSync waits for its synchronous process/stdio result; its timeout cannot prove
absence of arbitrary descendants or interrupt indefinitely blocked kernel I/O.
It is not a substitute for the separately reviewed asynchronous history transport
exit/stdout/close protocol. No executable can be authenticated solely by a caller
JSON/hash assertion; enrollment/provenance and execution approval stay external.

Before any real history connection: independent review and exact-source approved

availability evidence and separate authorization for the actual three-object run.
