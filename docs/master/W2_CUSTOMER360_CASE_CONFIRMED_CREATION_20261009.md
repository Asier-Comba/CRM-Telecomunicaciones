# W2 — confirmed current read after case creation

CaseCreate previously closed its drawer and refreshed the customer upon the case.create receipt, without reading the created case. It now retains the exact reviewed input and confirmed receipt, and reads case.get before closing, refreshing Customer360/inventory and showing a link to the actual current record. Both Customer360 and workspace inventory use the same creator.

The current record must match id/customer/contract/service/line/manual source and be at least as recent as the receipt. At the receipt version it must also match title/type/priority/due date/assignee. At a newer version, subsequent legitimate edits or reassignment remain visible rather than being compared to stale mutable values. The SQL trigger already makes ancestry/source immutable; no backend or authority change is needed.

Unknown command delivery preserves the existing frozen input/command_id and explicit same-operation retry. Once a receipt is confirmed, read failure keeps every field locked and exposes Consultar incidencia registrada, which only reads the cached id. There is no further case.create, optimistic count, automatic retry, private note query or operator send. Existing pre-receipt error handling and single-flight protection remain.
