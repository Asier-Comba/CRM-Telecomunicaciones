## Architecture comparison

The new route files are server gates and minimal projections. Product behavior lives under `src/features/{dashboard,customers,portfolio,opportunities,calendar,assistant,billing,settings,inbox,automations,documents}`. Historical runtime monoliths are not imported. Existing backend/auth/tenant boundaries remain owned by W1/W5; assistant semantics remain W3. Synthetic fixture constants are not bundled through presentation formatting imports, and production closure checks cover all product routes.

Generic calculation and PDF concepts were retained without property fields. The local parser fixes UTC date arithmetic across daylight-saving transitions, rejects invalid monetary values, distinguishes ambiguous customers and requires missing fields to be reviewed. Optional model extraction is a closed bounded validator, not a wired provider.

## Screenshot review limits

Nine screens are captured in both Desktop Chrome (1280×720) and Pixel 7 Chromium (393×800 CSS pixels). Top and lower viewport captures cover the application's scrolling main area. Internal tables and calendar use intentional horizontal scrolling; the document itself must not overflow. Temporary login toasts are awaited before capture. The assistant response area scrolls separately from its composer.

Initial review found a mobile opportunity search that collapsed, an overlapping assistant composer, technical response labels and missing Documents navigation. These have dedicated fixes and renewed evidence. Screenshots are human review artifacts, not pixel-diff certification. An independent old/new visual acceptance and actual microphone recognition remain outstanding.
