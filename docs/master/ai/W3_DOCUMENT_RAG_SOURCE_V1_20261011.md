# Authorized document source admission v1 — inert candidate

`src/assistant/document-rag-source-v1.ts` prepares an opaque, immutable source handle for a future server ingestion pipeline. This is not connected to an application route or assistant tool. There is no extraction implementation, index write, embedding call, retrieval, model call, database migration, vector database or activated provider. Operational RAG remains NOT_TESTED.

The trusted server dependencies must select the current authenticated actor/workspace/membership epoch/role, resolve an offered opaque document reference, and recheck the concrete document and target permission. Owner/admin admission preserves the existing `DocumentContentServiceV1` limit. Backend document metadata alone does not approve indexing: the source must be active, explicitly approved as reviewed knowledge, have an exact version/size/SHA256, and be a supported PDF document class. Identity and billing classes reject even if an adapter mistakenly approves them. This opt-in is an internal contract requirement, not an implemented classification workflow or privacy certification.

The future download adapter must use existing authorized tickets and the document content service, not raw Storage URLs or privileged bypasses. Download bytes are copied, size/hash checked against the exact approved revision, and passed only to the injected trusted extraction adapter. Document and membership are rechecked before extraction and after it. Revocation, changed actor/workspace/epoch/role/version/content or withdrawn indexing approval discards the preparation. A prepared handle itself cannot authorize persistence: the consumer must obtain fresh server scope/document admission, and any future index transaction must atomically verify the revision and current authority.

Extracted pages must be an ordinary exact record array, numbered sequentially, with no accessor/private fields, invalid Unicode, forbidden controls or high-confidence secret values. Limits: 100 pages, 200000 text bytes, 200 chunks, 2048 bytes per chunk. Unicode code points remain intact; UTF16 offsets identify the exact extraction substring and each chunk has its own SHA256. There is no overlap or semantic paragraph ranking in this first boundary. Extractor page/offset fidelity still requires actual parser/PDF evidence. Every fragment is marked `untrusted_document_data`; instructions embedded in documents stay literal data and acquire no tool/tenant/role authority. Passing structural checks does not certify that arbitrary document content is safe or free of sensitive personal data.

The internal admitted-material consumer rejects forged handles, a changed authority/revision and withdrawn approval. Exact snapshot comparison uses pinned field ordering. The embedding interface is typed only; a provider in `not_configured` state is not a semantic index. No fabricated embedding vectors or mocked model results are presented as operational RAG.

Nine targeted deterministic tests cover Unicode offsets/hash/limits, injection remaining data, missing approval, restricted roles, sensitive classes, changes during download/extraction, corrupt bytes, malformed/accessor/sparse pages, secrets, invalid Unicode, forged/stale handles and cancellation. Full local assistant suite617 PASS; targeted lint and strict ES2017 types PASS. Inputs use synthetic bytes and an injected extraction fixture: actual Auth/Storage/PDF extraction/embeddings/retrieval/model/W4 acceptance are NOT_TESTED. Source SHA and own combined CI will be recorded separately after publication.

Next units: connect a reviewed authorized metadata/ticket adapter and actual extractor; versioned atomic indexing with current-scope/revision checks; tenant/document-filtered retrieval with immediate permission revalidation; invalidation on edits/revocation/archive/delete; reproducible reindexing and retention/deletion; verified source citations; then authorized configured embeddings/hybrid ranking and real-provider evaluation. Do not register a RAG capability until its own controls are complete. Business writes remain OFF; issue10 and independent acceptance remain open.
