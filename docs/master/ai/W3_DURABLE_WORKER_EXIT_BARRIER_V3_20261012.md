# Durable v3 worker exit barrier

The acceptance runner previously resolved a worker result immediately on its IPC reply and cleared the30s timeout. A worker could report before parent start, replace its backend identity, report and exit abnormally, or report and remain alive while the parent started inspecting/recovering. The original worker body and PostgreSQL ports are unchanged; the parent protocol now checks order and observed termination through `scripts/durable-process-worker-controller-v3.mjs`.

The controller admits one valid ready identity, freezes it, and allows one parent start. A result is admissible only after start and without a requested cut. It succeeds only after observed exit code0 without signal. A requested cut requires its exact checkpoint and observed SIGKILL. Duplicate/invalid/unexpected messages fail closed. The timeout stays active until exit; failure rejects both pending barriers, preventing peers from waiting indefinitely. No raw adapter error or private environment is serialized.

Seven process tests run real independent Node workers with deliberately synthetic backend identifiers. The unchanged parentB0BF launch implementation fails six of these seven checks, including premature replies, invalid/substituted identity, abnormal exit and success before process exit.
