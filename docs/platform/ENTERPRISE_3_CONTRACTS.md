# Disposable operational contracts

CRM mail: `scripts/platform/mail-sink.mjs` accepts only `example.invalid` recipients and senders. Every enqueue and dispatch invokes the injected authority; consent and tenant/actor bindings must match. Registered templates, immutable payload/idempotency bindings and bounded queue/attempt counts precede capture. Twenty concurrent dispatch attempts capture once within one process. Signed, timely, bounded, single-use bounce receipts bind the captured message to its tenant. Audit excludes recipient, sender, actor, tenant and body values. This in-memory disposable contract is not a durable hosted outbox, SMTP provider or restart-proof dispatcher. W2 must supply accepted authority, approved template/consent storage and durable outbox before production integration.

Auth mail: a separate empty Linux runner uses canonical migrations in a temporary copy and the pinned Supabase CLI's local Mailpit. The script exercises Spanish confirmation/recovery/invite templates, local message envelopes, unconfirmed login rejection, exact redirect, foreign redirect rejection, single-use link rejection, mail rate limit, login after confirmation and actual elapsed recovery expiry. Only named check results are retained; mailbox bodies, addresses, tokens, sessions and verification URLs stay in process memory and are removed with the stack. CI results, not the script's existence, determine evidence. Actual stopped-SMTP recovery failure, revoked refresh and22 local checks pass; independent external deliverability remains unproven.

Offsite: `offsite-contract.mjs` requires a separately owned destination account, exact bucket/region, read+write without delete, version/immutability and approved retention. Authenticated encrypted bytes must read back by exact version and decrypt before simulated success. Wrong account/region, deletable access, short retention, corruption and interrupted writes stop the contract. Repetition cannot shorten existing retention. There is no selected real offsite adapter; mock account labels and policy approval are not company approval or geographic guarantees. Key rotation authenticates the original before producing and verifying a new key version; the old archive remains readable until an independently approved retention/retirement policy.

Monitoring: `monitor-contract.mjs` allows aggregate errors/queue/duration/backup age/certificate expiry/retries, plus random internal correlation and source SHA. Missing metrics and unavailable providers degrade health. A local sink deduplicates unchanged failures, records a changed incident/recovery recurrence and never sends external notifications. Private payload fields are stripped. Rotation mock contracts test stage → new health → switch → revoke → old denied; new-health failure rolls back before switching. Real databases/providers may have different rotation semantics, requiring accepted adapters and rollback policy.

Proxy: the API location uses HTTP/1.1, explicit Upgrade/Connection mapping, bounded connect/send/read times, disabled buffering/cache and private no-store on every API response. Forwarded host/protocol/client values are replaced by the proxy. TLS certificates, trusted ingress topology, SSE heartbeat/timeout policy remain company configuration requirements. Actual disposable nginx TLS, SSE, Upgrade, Host rejection, limits and metadata log checks pass. No wildcard domain or DNS mutation occurs.
